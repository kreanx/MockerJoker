# MockerJoker — Руководство пользователя

Расширение для подмены HTTP-запросов в браузере. Позволяет тестировать поведение приложения при ошибках сервера, задержках, отсутствии авторизации и других сценариях — без доступа к серверу.

---

## Установка

### Google Chrome

1. Скачайте архив `mock-extention-chrome.zip` и распакуйте его в любую папку
2. Откройте Chrome и перейдите по адресу `chrome://extensions`
3. Включите переключатель **«Режим разработчика»** (справа вверху)
4. Нажмите кнопку **«Загрузить распакованное расширение»** (Load unpacked)
5. Выберите распакованную папку
6. В панели инструментов появится иконка расширения

### Mozilla Firefox

1. Скачайте архив `mock-extention-firefox.zip` и распакуйте его в любую папку
2. Откройте Firefox и перейдите по адресу `about:debugging`
3. Слева выберите **«Этот Firefox»** (This Firefox)
4. Нажмите **«Загрузить временное дополнение»** (Load Temporary Add-on)
5. Выберите файл `manifest.json` из распакованной папки
6. В панели инструментов появится иконка расширения

> **Важно для Firefox:** временное дополнение пропадает после перезапуска браузера. Нужно загрузить заново.

---

## Первый запуск

1. Откройте тестируемое приложение в браузере
2. Нажмите на иконку расширения в панели инструментов
3. Убедитесь, что переключатель **«Включено»** в самом верху включён
4. Готово — расширение перехватывает запроси на открытой странице

> **Переключатель «Включено»** — это мастер-переключатель. Когда выключен, все правила игнорируются и запросы идут на настоящий сервер.

## Быстрый старт: пресеты

Пресеты — это готовые правила для типичных сценариев тестирования. Нажмите на нужный пресет, откроется редактор — введите URL-паттерн и сохраните.

### Доступные пресеты

| Пресет | Что делает | Что тестирует |
|---|---|---|
| **500 Internal Error** | Возвращает ошибку 500 с JSON-телом | Как приложение показывает ошибки сервера |
| **403 Forbidden** | Возвращает ошибку 403 | Как приложение показывает запрет доступа |
| **401 Unauthorized** | Возвращает ошибку 401 | Поведение при невалидном/просроченном токене |
| **204 No Content** | Возвращает пустой ответ (204) | Как приложение обрабатывает пустые данные |
| **Частичные данные** | Возвращает JSON с частью полей | Как приложение работает с неполными данными |
| **Убрать Authorization** | Удаляет заголовок Authorization из запроса | Поведение при отсутствии токена авторизации |
| **Убрать Cookie** | Удаляет заголовок Cookie из запроса | Поведение при отсутствии куки |

### Как использовать пресет

1. Нажмите на иконку расширения
2. Нажмите на нужный пресет (например, **«500 Internal Error»**)
3. Откроется редактор — в поле URL-паттерн введите маску (например, `*/api/users*`)
4. Поле URL-паттерн автоматически покажет URL реальных запросов с текущей страницы — выберите нужный
5. Нажмите **Сохранить**
6. Правило применится сразу, без перезагрузки страницы

## URL-паттерны

URL-паттерн определяет, на какие запросы действует правило.

### Поддерживаемые символы

| Символ | Значение | Пример |
|---|---|---|
| `*` | Любое количество любых символов | `*/api/users*` |

### Примеры паттернов

| Паттерн | Что перехватывает |
|---|---|
| `*/api/users*` | Все запросы, содержащие `/api/users` в URL |
| `*example.com*` | Все запросы к домену example.com |
| `*/api/v1/*` | Все запросы к API версии 1 |
| `https://exact-url.com/data` | Только этот конкретный URL |

> **Совет:** Используйте `*` по краям паттерна — это самый частый вариант. Паттерн `*/api/orders*` перехватит и `https://server.com/api/orders`, и `https://server.com/api/orders/123`.

## Счётчик перехватов

Рядом с каждым правилом отображается счётчик — сколько запросов оно перехватило.

- **Серый `0`** — правило не перехватило ни одного запроса. Проверьте URL-паттерн
- **Зелёный `3`** — правило перехватило 3 запроса. Наведите чтобы увидеть время последнего перехвата

## Создание правила вручную

Нажмите **«+ Добавить правило»** для создания правила с нуля.

### Поля правила

**Основные:**

- **Название** — любое описание для себя (например, «Мок для списка пользователей»)
- **URL-паттерн** — маска URL (см. раздел выше)
- **HTTP-метод** — GET, POST, PUT, DELETE или ANY (любой)

**Тип действия — Mock (подмена ответа):**

- **Статус-код** — HTTP-код ответа (200, 404, 500 и т.д.)
- **Задержка (мс)** — задержка перед ответом в миллисекундах. Полезно для тестирования спиннеров, таймаутов, медленного интернета
  - `0` — без задержки
  - `1000` — 1 секунда
  - `5000` — 5 секунд
  - `30000` — 30 секунд (имитация зависшего сервера)
- **Заголовки ответа** — HTTP-заголовки, которые вернёт подменённый ответ
- **Тело ответа** — JSON, который вернётся вместо реального ответа сервера
  - Поле поддерживает **подсветку синтаксиса** JSON (ключи, строки, числа подсвечены разными цветами)
  - **Валидация** — под полем отображается статус: "Valid JSON" или текст ошибки
  - **Форматировать** — кнопка для автоформатирования JSON с отступами
  - **Fullscreen** (кнопка ⛶) — разворачивает редактор на весь экран с тёмной темой
  - При **вставке** JSON из буфера — автоматически форматируется

**Тип действия — Modify (изменение запроса):**

- **Удалить заголовки** — заголовки, которые будут удалены из запроса перед отправкой
- **Добавить/заменить заголовки** — заголовки, которые будут добавлены в запрос

## Сценарии тестирования

### Сценарий 1: Ошибка 500 Internal Server Error

Тестируем: как приложение показывает ошибку сервера.

1. Нажмите пресет **«500 Internal Error»**
2. Введите URL-паттерн, например `*/api/orders*`
3. Сохраните — правило применится сразу
4. Приложение должно показать сообщение об ошибке

### Сценарий 2: Ошибка 403 Forbidden

Тестируем: как приложение показывает запрет доступа.

1. Нажмите пресет **«403 Forbidden»**
2. Введите URL-паттерн
3. Сохраните
4. Приложение должно показать сообщение о запрете доступа

### Сценарий 3: Частичные / невалидные данные

Тестируем: как приложение работает с неполными данными от сервера.

1. Нажмите пресет **«Частичные данные»**
2. Введите URL-паттерн
3. Нажмите на созданное правило для редактирования
4. Измените **Тело ответа** — удалите нужные поля или измените значения:
   ```json
   {
     "id": 1,
     "name": "John Doe"
   }
   ```
   Например, уберите поле `email`, или измените `id` на строку `"abc"`, или замените весь JSON на `null`
5. Сохраните

### Сценарий 4: Отсутствие авторизации (401)

Тестируем: поведение при невалидном или отсутствующем токене.

**Вариант A — сервер возвращает 401:**

1. Нажмите пресет **«401 Unauthorized»**
2. Введите URL-паттерн
3. Сохраните

**Вариант B — токен не отправляется:**

1. Нажмите пресет **«Убрать Authorization»**
2. Введите URL-паттерн
3. Сохраните — запрос пойдёт на реальный сервер, но без заголовка Authorization

### Сценарий 5: Медленный сервер / таймаут

Тестируем: спиннеры, сообщения «Сервер не отвечает», retry-механизмы.

1. Нажмите пресет **«500 Internal Error»** (или любой другой)
2. Введите URL-паттерн
3. Отредактируйте правило — в поле **«Задержка (мс)»** введите нужное значение:
   - `3000` — 3 секунды (проверка спиннера)
   - `10000` — 10 секунд (проверка long loading)
   - `30000` — 30 секунд (проверка таймаута)
4. Сохраните

### Сценарий 6: Пустой ответ от сервера

Тестируем: как приложение обрабатывает отсутствие данных.

1. Нажмите пресет **«204 No Content»**
2. Введите URL-паттерн
3. Сохраните

## Полная панель (Panel)

Popup закрывается при клике вне его. Для удобной работы с большим количеством правил используйте полную панель:

1. Нажмите на иконку расширения
2. Нажмите кнопку **«Открыть панель»** внизу popup
3. Откроется полноэкранный интерфейс в новой вкладке

В панели доступны:

- Все пресеты и редактор правил
- **Экспорт** — сохранить все правила в JSON-файл
- **Импорт** — загрузить правила из JSON-файла (передать коллегам)

### Экспорт / Импорт правил

**Экспорт:**

1. Откройте панель
2. Нажмите **«Экспорт правил»**
3. Сохраните файл

**Импорт:**

1. Откройте панель
2. Нажмите **«Импорт правил»**
3. Выберите JSON-файл с правилами
4. Правила добавятся к существующим

> **Совет:** Создайте набор правил для типичных сценариев, экспортируйте и передайте коллегам через сетевую шару или чат.

## Частые проблемы

### Расширение установлено, но правила не работают

- Убедитесь, что мастер-переключатель **«Включено»** включён
- Проверьте, что правило **включено** (переключатель рядом с правилом)
- Проверьте, что URL-паттерн совпадает с реальным URL запроса (откройте DevTools → Network)
- Попробуйте обновить страницу (F5)

### После перезапуска Firefox расширение пропало

Firefox не сохраняет временные дополнения. Загрузите заново: `about:debugging` → This Firefox → Load Temporary Add-on.

### Правило не перехватывает запрос

- Проверьте HTTP-метод — если стоит `GET`, а запрос `POST`, правило не сработает. Используйте `ANY`
- Расширение перехватывает только `fetch` и `XMLHttpRequest`. Навигация, `<script src>`, `<img>` — не перехватываются

### Хочу отредактировать тело ответа

Нажмите на правило в списке — откроется редактор. Измените **Тело ответа** и нажмите **«Сохранить»**.

### Как удалить правило

Нажмите на значок корзины рядом с правилом. Или откройте правило на редактирование и нажмите **«Удалить»**.

---

## Ограничения

- Перехватываются только запросы через `fetch()` и `XMLHttpRequest`
- Навигация (переход по ссылкам), загрузка скриптов, картинок, стилей — **не перехватываются**
- Заголовки `Cookie`, `Host`, `Connection` и другие forbidden-заголовки нельзя удалить через modify (ограничение браузера)
- Все мокированные запросы помечаются в **консоли разработчика** (F12 → Console) красной записью `[MockerJoker]`
